# תוכנית — Milestone 3: שמע, השהיה והמשך משחק

**מטרה:** להשלים את חוויית המשחק לשימוש אמיתי בטלפון: צלילים (ניתנים להשתקה) בהצגת הרצף ובלחיצות השחקן, והשהיה אוטומטית ובטוחה כשעוזבים את מסך המשחק, מסתירים את האפליקציה או פותחים את חלונית האישור. כל המצב בזיכרון בלבד.

## 1. מה נכנס ומה לא

**נכנס:**
- ארבעה צלילים שונים (Web Audio API), המושמעים גם בזמן הארת כל צבע בהצגת הרצף וגם בלחיצת שחקן.
- כפתור הפעלה/השתקה במסך המשחק (משני, מתחת ל״התחל״). השתקה לא משפיעה על חוקי המשחק או ההארות.
- לחיצת שחקן מתבהרת לרגע קצר (כ־150ms); ההארה החזקה עם הזוהר נשארת להצגת רצף בלבד (כבר קיים ב-CSS מ-M2 — רק לוודא).
- השהיה כשהמשחק לא גלוי במסך המשחק: מעבר ל״אודות״, הסתרת האפליקציה/נעילת מכשיר (`visibilitychange`), וחלונית האישור ״משחק חדש״.
- חידוש: רצף שנקטע מוצג שוב **מהצבע הראשון**, אותו רצף ואותו שלב; בתור השחקן נשמר `inputIndex`.
- טיפול בהשהיות חופפות (חידוש רק כשכולן הסתיימו) ובכישלון Web Audio (המשחק ממשיך בלי צליל).
- בדיקות Vitest להשהיה/חידוש ולשמע; רשימת בדיקות ידניות.

**לא נכנס:** PWA, התקנה, GitHub Actions (M4). שמירת השתקה בין רענונים (לא נדרש; ברירת מחדל ״לא מושתק״ בכל טעינה). אין שינוי ב-`engine.ts` — השהיה היא עניין של ממשק ותזמון, לא של חוקי המשחק.

## 2. החלטות מימוש (פשוט ככל האפשר)

- **שמע (`audio.ts`):** `AudioContext` נוצר בעצלות דרך `unlock()` הנקרא בלחיצות ״התחל״ / ״לשלב הבא״ / ״שחק שוב״ ובכל לחיצת pad (מחוות משתמש, כמו שהדפדפנים דורשים), ו-`resume()` בכל קריאה כזו (iOS לפעמים משעה אותו אחרי הסתרה). כל צליל: `OscillatorNode` + `GainNode` עם עלייה/דעיכה קצרה (כ־10ms / כ־250ms) נגד "קליקים". תדרים שונים בבירור (החלטת מימוש, לא דרישת מוצר): אדום 330Hz, כחול 262Hz, צהוב 392Hz, ירוק 523Hz. כל הקוד בתוך `try/catch` — כישלון ביצירה או בניגון נבלע בשקט והמשחק ממשיך. המודול מקבל מפעל `AudioContext` שאפשר להחליף בבדיקות.
- **השתקה:** `isMuted` מתחיל ב-`false`, שמור במודול השמע (זיכרון בלבד). המשחק קורא ל-`audio.play(color)` והמודול מחליט אם לנגן.
- **השהיה (`pause.ts`, לוגיקה טהורה ללא DOM):** `createPauseController(onPause, onResume)` שמחזיק קבוצת סיבות פעילות: `'about' | 'hidden' | 'confirm'`. `pause(reason)` מפעיל `onPause` רק במעבר מ-0 ל-1 סיבות; `resume(reason)` מפעיל `onResume` רק כשהקבוצה מתרוקנת. כך השהיות חופפות עובדות לבד, וחזרה כפולה/ריקה לא עושה כלום.
- **חיבור ב-`views/game.ts`:**
  - `onPause`: `presenter.cancel()` (מבטל טיימרים ומנקה הארה), ביטול טיימר ההבהוב של לחיצה, חסימת הלוח.
  - `onResume`: אם `phase === 'showing'` — `play()` (אותו `state.sequence` מההתחלה); אחרת `render()` בלבד (ב-`playerTurn` ה-`inputIndex` נשאר).
  - חלונית האישור עוברת לאותו מנגנון (במקום `confirmOpen` הנפרד מ-M2): פתיחה = `pause('confirm')`, סגירה בכל דרך (ביטול/Esc) = `resume('confirm')`. אישור ״משחק חדש״ מאפס את המשחק, ואז סוגר את החלונית — החידוש מנגן את הרצף החדש פעם אחת בלבד (לוודא שאין הצגה כפולה).
  - `visibilitychange`: `document.hidden` → `pause('hidden')`, אחרת `resume('hidden')`. בטעינה: אם הדף כבר מוסתר — מתחילים כמושהים.
  - הממשק החדש של ה-view: `setActive(active: boolean)` — `false` = `pause('about')`, `true` = `resume('about')`.
- **ניווט (`nav.ts`):** `createNav` מקבל callback אופציונלי `onChange(name)`. ב-`main.ts` מחברים: `onChange: (name) => gameView.setActive(name === 'game')`. שני המסכים נשארים מוצגים ב-DOM כמו היום (רק `hidden`), כך שהמצב נשמר.
- **לחיצת שחקן:** ב-handler של ה-pad, רק אם `state.phase === 'playerTurn'` ולא מושהה: הבהוב קצר + `audio.play(color)` + `pressColor`. לחיצה שגויה גם מנגנת את הצליל של הצבע שנלחץ (כל לחיצה = צליל). אין צליל נפרד בסיום שלב, בניצחון או בהפסד.
- **צליל בהצגת הרצף:** ב-callback `onLit` שמועבר ל-`presenter.show`, כשהצבע נדלק (לא `null`) — `audio.play(color)` לצד ההארה. `presenter.ts` עצמו לא משתנה (נשאר טהור ובדיק); הצליל נקצר/מתעצם לפי ה-Envelope הקבוע (~250ms) ולכן לא חורג מהארה של 350ms בשלב 10. השתקה מבטלת גם את צלילי הרצף. השהיה מבטלת את הטיימרים, ולכן לא ינוגנו צלילים נוספים; צליל שכבר התחיל מסתיים לבד (עד ~250ms). בהצגה חוזרת אחרי חזרה מהסתרה (`visibilitychange`) אין מחוות משתמש — אם הדפדפן חוסם את השמע, ההצגה ממשיכה בלי צליל (כמו שמוגדר ב-ARCHITECTURE).
- **שאר מצבים בהשהיה:** `idle`, `levelComplete`, `won`, `lost` — אין תזמונים, ולכן ההשהיה רק חוסמת קלט ולא משנה כלום; ההודעות והכפתורים נשארים.
- **כפתור השתקה (UI):** כפתור משני עם אייקון ~24px (רמקול / רמקול מושתק, SVG מוטבע) וטקסט עברי: ״השתקת צלילים״ כשהצלילים פועלים, ״הפעלת צלילים״ כשהם מושתקים; הטקסט מתעדכן (בלי `aria-pressed` כדי לא לקרוא פעמיים). מוצג תמיד במסך המשחק, גם לפני תחילת משחק, מתחת לכפתור הראשי ולצד/מעל ״משחק חדש״ לפי ה-Wireframes. מגע ≥ 44px.

**ליצור:**

## 5. בדיקות

**אוטומטיות (Vitest, סביבת node, בלי DOM):**
- `pause.test.ts`: סיבה אחת → `onPause` פעם אחת, `onResume` בחזרה; שתי סיבות חופפות (אודות + hidden) → חידוש רק אחרי שתיהן; `pause` כפול של אותה סיבה לא מכפיל; `resume` בלי `pause` לא מפעיל כלום; `isPaused` נכון בכל שלב.
- `audio.test.ts`: `play` יוצר אוסצילטור בתדר שונה לכל אחד מארבעת הצבעים; מושתק → לא נוצר כלום; `setMuted` חוזר ומאפשר; מפעל שזורק שגיאה / `resume` שנדחה / `start` שזורק → `play` לא זורק; ניסיון חוזר אחרי כישלון לא שובר.
- `presenter.test.ts` (קיים): כבר מכסה ביטול וחידוש מההתחלה בלי טיימרים ישנים; להוסיף מקרה אם ההשהיה חופפת להפסקה בין צבעים.
- בדיקת שילוב קטנה: הרצף שמוצג אחרי `cancel` + `show` זהה לרצף ב-`GameState` (אין שינוי ברצף או בשלב) — נשענת על כך שההשהיה לא נוגעת ב-`engine`.
- `npm run test`, `npm run typecheck`, `npm run build` עוברים.

**ידניות (דפדפן מובייל, או Chrome DevTools במצב מובייל; iPhone/Safari ו-Android/Chrome מלאים ב-M4):**
- ארבעה צלילים שונים בלחיצה; בזמן הצגת רצף כל צבע מושמע בהארתו (כולל צליל נכון לכל צבע); השתקה/הפעלה חוזרת; משחק זהה בהשתקה.
- הבהוב קצר בלחיצה, בלי זוהר חזק; זוהר חזק רק בהצגת רצף.
- מעבר לאודות באמצע הצגה ← חזרה: אותו רצף מההתחלה, אותו שלב. באמצע תור שחקן (למשל 2 מתוך 4) ← חזרה: ״2 מתוך 4״ נשמר.
- החלפת לשונית / נעילה / אפליקציה אחרת ← אותו דבר; בדיקה שהרצף לא רץ ברקע (חזרה מוקדמת).
- חלונית אישור ← ביטול באמצע הצגה; אישור ״משחק חדש״ בתוך הצגה — אין הצגה כפולה או הארה תקועה.
- לחיצות מהירות לפני/אחרי השהיה לא משנות את ההתקדמות; חסימת קלט בזמן השהיה.
- חסימת שמע (מכשיר במצב שקט / דפדפן שחוסם) — המשחק ממשיך לעבוד.

## 6. סיכונים ונקודות לתשומת לב

- **iOS:** מתג צלצול במצב שקט עלול להשתיק Web Audio; זו התנהגות מערכת, לא באג. ל-`resume()` בכל לחיצה / התחלת שלב יש תפקיד בחזרה מרקע. הצגה חוזרת אחרי חזרה מהסתרה לא נובעת ממחוות משתמש, ולכן ב-iOS היא עלולה לרוץ בשקט עד הלחיצה הבאה.
- **כפילות חידוש:** אישור ״משחק חדש״ סוגר את החלונית ומפעיל `resume('confirm')`; חשוב שהמשחק החדש יתחיל פעם אחת בלבד (או שהחידוש מנגן, או שאישור מנגן — לא שניהם). הבנייה תבחר מסלול אחד ותכסה בבדיקה ידנית.
- **הבהוב לחיצה אחרונה:** הלוח נחסם מיד אחרי לחיצה שמסיימת שלב; ההבהוב נשאר ב-CSS class ולא תלוי ב-`disabled`.
- הבהרה ל-PRD: לחיצה שגויה מנגנת את צליל הצבע שנלחץ לפני המעבר ל״המשחק נגמר״ (ה-PRD אומר "כל לחיצה משמיעה את הצליל"); אם תעדיפי שקט בלחיצה שגויה — לעדכן לפני הבנייה.

## 7. Definition of Done (תרגום לבדיקה)

1. לכל צבע צליל מובחן; הצליל מושמע בהצגת הרצף ובלחיצת שחקן; השתקה לא משנה תוצאות — `audio.test.ts` + ידני.
2. הבהוב קצר בלחיצה, זוהר חזק רק בהצגת רצף — ידני + עיון ב-CSS.
3. אודות ← חזרה והסתרה ← חזרה לא מאפסים — ידני.
4. רצף שנקטע חוזר מהצבע הראשון; בתור שחקן ההתקדמות נשמרת — `pause.test.ts` + ידני.
5. אין טיימרים ישנים ואין קלט בהשהיה — `presenter.test.ts` + `pause.test.ts` + ידני.
6. כישלון Web Audio לא מונע משחק — `audio.test.ts`.
