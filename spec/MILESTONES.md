# MILESTONES — משחק הזיכרון סיימון

**מסמכי מקור:** `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md`  
**היקף:** אפליקציית Web בעברית (RTL), Mobile First, עם שני מסכים, Frontend בלבד, PWA ו־Offline. אין Backend, Database, Authentication או AI.

## Milestone 1 — בסיס הפרויקט ומסכי האפליקציה ✅

**מטרה:** להעמיד אפליקציה ניתנת להרצה ולבדיקה במובייל, עם מבנה המסכים והעיצוב שנקבעו.

**מה יש לממש:**
- פרויקט Vite + TypeScript + CSS ו־Git Repository ב־GitHub, בהתאם ל־`ARCHITECTURE.md`.
- שני Views בלבד: ״משחק״ ו״אודות״, וניווט ביניהם ללא טעינה מחדש.
- מסך המשחק במצב ההתחלתי: כותרת, הוראה קצרה, לוח Simon עגול בארבעה רבעים, וכפתור ״התחל״. הלוח אינו פעיל לפני תחילת משחק.
- מסך ״אודות״: הסבר, הוראות משחק ושם היוצרת ״אוה סוקולובסקי״.
- שפה עיצובית על פי `DESIGN.md`, כולל צבעים, טיפוגרפיה, כפתורים, מרווחים ו־RTL; התאמה למובייל.

**תוצר מצופה:** אפליקציה מקומית עובדת, עם שני מסכים מעוצבים וניווט פעיל; המשחק עצמו עדיין אינו פועל.

**Definition of Done:**
- `npm install`, הרצת סביבת הפיתוח ו־Build מסתיימים בהצלחה.
- קיימים בדיוק שני מסכים, עם ניווט תקין הלוך ושוב ללא Refresh.
- מסך המשחק מציג את ארבעת צבעי הלוח בפריסת Simon העגולה, והם אינם מגיבים כלחצני משחק לפני התחלה.
- מסך ״אודות״ מציג את התוכן ושם היוצרת; הטקסט בעברית ו־RTL.
- נראות המסכים תואמת את המבנה ב־Wireframes ואת הסגנון ב־Style Guide וב־Mockups, בכפוף להבהרות ב־`DESIGN.md`.
- אין גלילה אופקית ברוחב טלפון; רכיבי המגע והניווט נגישים.

## Milestone 2 — מחזור משחק מלא של Simon ✅

**מטרה:** לאפשר משחק שלם מתחילתו ועד ניצחון או הפסד, ללא תלות בשמע או בהתקנה.

**מה יש לממש:**
- Game Engine עם State בזיכרון בלבד ו־10 שלבים; יצירת רצף אקראי המתחיל בצבע אחד ומתארך בצבע אחד בכל שלב, תוך שמירת הרצף הקודם ואפשרות לחזרות.
- לחיצה על ״התחל״, הצגת הרצף באמצעות הארה בלבד, ללא צלילים; חסימת קלט בזמן ההצגה.
- האצת הצגת הרצף מ־800ms בשלב 1 ל־350ms בשלב 10, לפי הנוסחה וההפסקה המוגדרות ב־`ARCHITECTURE.md`.
- ״תורך!״, חיווי התקדמות בלחיצות הנכונות ומספר שלב קבוע ״שלב X מתוך 10״; אין מגבלת זמן.
- מעבר לשלב הבא רק באמצעות ״לשלב הבא״ לאחר הצלחה; ניצחון בשלב 10, והפסד מיידי בלחיצה שגויה עם מספר השלב וכפתור ״שחק שוב״.
- כפתור ״משחק חדש״ במהלך משחק פעיל עם חלונית אישור וביטול; ״שחק שוב״ יוצר משחק חדש.
- בדיקות Vitest ללוגיקת הרצפים, מצבי המשחק, תוצאות ואיפוס.

**תוצר מצופה:** משחק מלא של 10 שלבים שניתן לשחק בו מתחילתו ועד סופו, עם כל הודעות המצב ופעולות ההתקדמות והאיפוס.

**Definition of Done:**
- כל משחק חדש מתחיל בשלב 1 וברצף באורך 1; כל מעבר שלב מוסיף בדיוק צבע אחד לסוף הרצף הקיים, עד לאורך 10.
- הרצף מוצג בסדר הנכון, בהארה בלבד, בקצב המתאים לשלב; לחיצות בזמן הצגה אינן משפיעות.
- לאחר ההצגה מוצגים ״תורך!״ וחיווי התקדמות המתעדכן רק בלחיצות נכונות; השחקן יכול להמתין ללא הגבלת זמן.
- השלמת שלבים 1–9 אינה מתחילה אוטומטית שלב חדש; שלב 10 מסתיים בניצחון.
- לחיצה שגויה מסיימת את המשחק מייד ומציגה ״המשחק נגמר״, השלב וכפתור ״שחק שוב״.
- ״משחק חדש״ מציג אישור במהלך משחק פעיל: ״ביטול״ משמר את המשחק, ואישור מתחיל משחק חדש ללא Timers ישנים.
- בדיקות Vitest למעברים המרכזיים ולמקרי הקצה עוברות, והמשחק נבדק ידנית בדפדפן מובייל.

## Milestone 3 — שמע, השהיה והמשך משחק ✅

**מטרה:** להשלים את חוויית המשחק בעת שימוש אמיתי בטלפון, כולל צלילים והפרעות במהלך משחק.

**מה יש לממש:**
- ארבעה צלילים ייחודיים באמצעות Web Audio API, המושמעים גם בהצגת הרצף (בזמן הארת כל צבע) וגם בלחיצת שחקן; כפתור הפעלה/השתקה במסך המשחק. לחיצת שחקן מתבהרת לרגע קצר בלבד (ללא הארת הרצף).
- השהיה בניווט למסך ״אודות״, בהסתרת האפליקציה ובנעילת המכשיר; המשך רק כשהמשחק גלוי במסך המשחק.
- אם ההשהיה אירעה בהצגת רצף: ביטול תזמונים והצגת **אותו רצף** מהתחלה בחזרה; אם אירעה בתור השחקן: שמירת הלחיצות הנכונות שכבר בוצעו.
- טיפול בהשהיות חופפות, בחלונית אישור ״משחק חדש״ ובכישלון בהפעלת שמע, בהתאם ל־`ARCHITECTURE.md`.
- בדיקות אוטומטיות ללוגיקת השהיה וחזרה, ובדיקות ידניות לשמע ולמחזור חיי הדף.

**תוצר מצופה:** משחק מלא עם שמע ניתן להשתקה, שממשיך באופן עקבי לאחר מעבר מסכים או הסתרת האפליקציה.

**Definition of Done:**
- לכל צבע צליל מובחן; הצליל מושמע בהצגת הרצף ובלחיצת שחקן, והשתקה אינה משנה את תוצאות המשחק.
- לחיצת שחקן מתבהרת לרגע קצר כסימן ללחיצה; ההארה החזקה של הרצף קיימת רק בעת הצגת רצף.
- מעבר ל״אודות״ וחזרה אינם מאפסים את המשחק; הסתרת האפליקציה והחזרה אינם מאפסים אותו כל עוד הדף נשאר טעון.
- רצף שנקטע מוצג שוב מהצבע הראשון ללא שינוי בסדר או בשלב; בתור השחקן נשמרת ההתקדמות שכבר בוצעה.
- אין Timers ישנים הממשיכים אחרי השהיה, איפוס או חידוש, ואין קלט משחק בזמן השהיה.
- כישלון של Web Audio אינו מונע משחק; בדיקות Vitest הרלוונטיות עוברות.

## Milestone 4 — PWA, Offline ופרסום ✅

**מטרה:** לאפשר התקנה ושימוש ללא אינטרנט ולפרסם את המשחק באופן אוטומטי דרך GitHub.

**מה יש לממש:**
- `vite-plugin-pwa` עם Web App Manifest, אייקונים מקומיים ו־Service Worker המאפשר Cache לכל נכסי שני המסכים.
- ב־Android/Chrome: הצגת ״התקן אפליקציה״ רק כאשר הדפדפן מציע התקנה ישירה; הסתרה לאחר התקנה או כשאין תמיכה. ב־iPhone: כפתור ״התקן אפליקציה״ שפותח חלונית הסבר להתקנה ב־Safari (שיתוף ← הוסף למסך הבית), ומוסתר כשהאפליקציה כבר מותקנת.
- הגדרת Vite Base Path, נתיב התחלה ו־Scope תואמים ל־GitHub Pages, ללא Routes עמוקים הדורשים Backend.
- GitHub Actions לבדיקות, Build ו־Deployment אוטומטי ל־GitHub Pages באמצעות HTTPS לאחר Push ל־`main`.
- בדיקות על iPhone/Safari ועל Android/Chrome, כולל שימוש Offline לאחר טעינה מוצלחת, מסך ״אודות״, צלילים, התקנה וחזרה ממשחק לאחר הסתרה.

**תוצר מצופה:** כתובת HTTPS ציבורית למשחק; אפליקציה ניתנת להתקנה במכשירים תומכים ופועלת Offline לאחר טעינה ראשונית מוצלחת.

**Definition of Done:**
- Push ל־`main` מפעיל אוטומטית בדיקות ו־Build; רק Build תקין נפרס בהצלחה ל־GitHub Pages.
- האתר נפתח בכתובת HTTPS ללא שגיאות נכסים או נתיבים, כולל אחרי רענון; רענון מתחיל משחק חדש.
- לאחר טעינה מוצלחת Online, המשחק ושני המסכים זמינים Offline, כולל השמעת צלילים שנוצרים מקומית.
- ב־Android/Chrome כפתור ההתקנה מופיע רק כשהתקנה ישירה זמינה; ב־iPhone הכפתור מופיע ופותח הסבר התקנה, ומוסתר אחרי ההתקנה.
- המשחק נבדק ב־iPhone/Safari וב־Android/Chrome: מגע, RTL, שמע, השהיה, חזרה, ניצחון, הפסד, PWA ו־Offline.
- אין שמירת התקדמות, Backend, Database, Authentication או שירות AI.

## Development Execution Rules — הוראות מחייבות ל־AI המפתח

1. יש לפתח את ה־Milestones **לפי הסדר** המופיע במסמך, בהתאם ל־`PRD.md`, `ARCHITECTURE.md` ו־`DESIGN.md`.
2. בסיום כל Milestone יש **לעצור את הפיתוח** ולהציג למשתמש את התוצר שהושלם, דרך לבדוק אותו ואת תוצאות הבדיקות בפועל מול כל סעיף ב־Definition of Done. יש לציין במפורש בדיקות שלא בוצעו או תנאים שלא הושלמו; אין לדווח על בדיקה שלא הורצה כאילו עברה.
3. **אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש.**
4. אין להוסיף פיצ'רים, מסכים, Backend, Database, שמירת התקדמות או Dependencies שאינם נדרשים במסמכי הפרויקט.
